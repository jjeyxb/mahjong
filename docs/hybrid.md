# 混合辨識（樣板＋YOLO）

在任一功能頁的「設定 → 畫面辨識方式」選擇 **混合辨識（樣板＋YOLO）**。三個功能頁的選單會沿用既有同步機制，一處改選，其餘兩處同步，並保存至下次啟動。已開啟的 MIA 需重新啟動以載入新選項。

網頁版的 AI 建議若要走混合辨識，仍需在 AI 建議頁勾選「使用圖像辨識」；放銃分析可用既有的「強制使用圖像辨識」選項。封包來源不受辨識後端選擇影響。

## 運作方式

```text
同一張已校正的 1920×1080 畫面
  → YOLO：區域與牌的位置、牌面候選
  → 樣板：核對手牌，以及投影攤平後的牌河／副露候選
  → 合併同一幀的辨識證據
  → 唯一的事件追蹤器與可修訂事件帳
  → MIA 快照檢查、Mortal 重播、Log 與放銃分析
```

本版共用 YOLO 的定位，在同一候選位置進行雙牌面辨識。YOLO 漏掉的候選位置不會憑空由合併層補出；這個限制與同時運行兩套完整定位器不同。既有的純樣板模式仍可獨立選用。

GPU 推論仍在原本 Python 3.12 子程序，樣板核對由 MIA 的工作執行緒執行。子程序先回傳原始觀測，等合併結果傳回後才更新事件追蹤，因此同一幀只進事件追蹤一次。沒有把兩條獨立 MJAI 事件流相加。

## 合併規則

- **一致：** 保留原牌面；低信心 YOLO 候選需兩次近期強樣板證據後，才提升為追蹤器可採用的候選。
- **YOLO 信心不足、樣板穩定：** 樣板分數至少 0.75、與第二名差距至少 0.10、亮度至少 0.65，且同一位置有兩次近期強證據，才可改判牌面。
- **兩者對手牌都有強證據卻不一致：** 暫停該牌面定案與依賴它的建議，等待後續畫面。原始候選、原始 YOLO 信心值及樣板分數都保留。
- **樣板證據不足：** 沿用 YOLO；不強迫每張牌都要通過樣板。
- **赤五／普通五爭議：** 不用牌河合併赤五後的模板差距直接改色，保留原 YOLO 與既有赤五判定。
- **橫置牌：** 保留現有樣板版對橫置牌的保守政策，不把原本刻意不可信的猜測升成強證據；繼續由 YOLO、時序與麻將規則處理。

對手牌河／副露的強證據衝突會記錄，強 YOLO 候選仍保留給追蹤與牌數檢查；本版不因一張舊牌河的衝突而永久停止整場建議。

樣板分數是相關係數，YOLO 分數是模型輸出，沒有直接比大小。合併後沿用追蹤器的 `conf` 欄位作為相容性門檻；改動該欄位時另保存 `raw_yolo` 與 `template`，不能將合併後的值當成重新校準過的機率。

## 速度與資源

新樣板比對每幀預設最多 24 次，新增比對的時間預算為 50 ms。到達預算後，仍可使用像素完全相同的已快取結果；其餘候選保留 YOLO 輸出。投影、快取查詢等仍有額外耗時，因此 50 ms 不是整幀耗時的硬上限。

優先核對低信心候選、手牌與較久未檢查的位置。快取有容量上限；位置相近的兩張牌不會只因牌名相同就合併，舊的樣板投票也不會跨越長時間缺乏證據的間隔。

只新增核對層，沒有修改原樣板分類器、牌河投影、TableWorker 或既有追蹤器的實作。

## 驗證與重跑

混合模式以既有真人錄影、原始 YOLO 觀測及原時間戳驗證；封包僅在重播完成後作為答案。重播時同時讀取原 JPEG，才能讓樣板與 YOLO 的證據對齊同一幀：

```sh
.venv/bin/python tools/replay_hybrid.py data/recordings/human-20261104-185744 \
  --observations out/yolo-eval-20261105/human-20261104-mps/observations.ndjson \
  --out out/hybrid-recheck --engine
```

輸出包括 `vision.jsonl`、`fusion.jsonl` 與 `summary.json`。`fusion.jsonl` 記錄改判、信心門檻調整及尚未解決的歧異。數字按觀測次數統計，同一張牌可能出現多次，不能把「改判次數」解讀為「改對幾張真實牌」。

驗證結果保存在 `out/hybrid-20261106/`。單一場次若純 YOLO 已經全部辨識正確，混合模式的最終數字可能相同；仍需以更多困難素材衡量首次輸出、漏讀與建議是否趕在出牌前。這個模式不保證在所有場景都更準或更快。

2026-11-06 的最終版本以真人東風場 5 局、7,468 個原始觀測時間點重播：捨牌 198/198、自摸 49/49、副露 12/12，沒有多報或牌面錯誤，Mortal 重播錯誤為 0。這是完整重播後的事件結果，與已修整的純 YOLO 流程相同，不能當作每幀辨識率或即時建議成功率。

有封包可對照的局部例子包含「低信心九萬 → 北」與「低信心發 → 東」；已將對應牌面裁圖保留為回歸測試。這些修正跨多個時間點重複出現，不代表改對同等數量的獨立牌。

本次額外核對耗時平均 21.57 ms、中位 4.01 ms、p95 65.26 ms、最大 114.75 ms；這是在現成 YOLO 觀測與原 JPEG 上量測的新增工作，沒有包含重新執行整段 YOLO 推論。實際 MPS 程序已通過短片段通訊與辨識測試，完整真人局的即時負載與掉幀情況尚未驗證。對手捨牌確認仍有最長 20.58 秒的延遲。

## 與其他修改的邊界

混合辨識放在新增的 `src/mia/hybrid/`，既有 YOLO 的程序通訊與工廠只增加必要接點。Claude 的三頁選單布局與同步邏輯沿用，僅在既有選項建立處新增一列。施工前的工作樹快照、修改範圍與同時發生的外部更新保存在 `out/hybrid-20261106/`，沒有將 Claude 正在修改的檔案回復成舊快照。
