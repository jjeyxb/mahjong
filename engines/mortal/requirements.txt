# Mortal AI 引擎子程序環境 — 必須是 Python 3.12
#
# 為什麼要獨立環境:
#   1. libriichi 不在 PyPI,需從 Mortal repo 自行編譯;
#      mjai (mjai.app simulator) 在 PyPI 上只有 cp312 wheel。
#      兩者都無法在主程式的 Python 3.14 環境安裝。
#   2. torch 載入慢且可能崩潰,不應拖垮 UI 主進程。
#   3. 多模型比較:同時啟動多個引擎子程序,餵同一條事件流。
#
# 授權隔離**不是**理由 —— 主專案本身就採 AGPL-3.0(見根目錄 LICENSE)。
# 子程序 + MJAI stdio 通訊一般視為獨立程式,但那只是附帶效果,
# 上面三個技術限制本身就足以決定架構。
#
# ---------------------------------------------------------------------------
# 建置步驟(macOS Apple Silicon 已實測,2026-07-29)
# ---------------------------------------------------------------------------
#   brew install python@3.12
#   curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh -s -- -y
#
#   python3.12 -m venv engines/mortal/.venv
#   engines/mortal/.venv/bin/pip install -r engines/mortal/requirements.txt
#
#   git clone --depth 1 https://github.com/Equim-chan/Mortal.git engines/mortal/Mortal
#   cd engines/mortal/Mortal
#   PYO3_PYTHON=$(which python3.12) cargo build -p libriichi --lib --release
#
#   # 產物名稱依平台而異(libriichi 的 [lib] name 是 "riichi"):
#   #   macOS  : cp target/release/libriichi.dylib mortal/libriichi.so   ← 見下方註記
#   #   Linux  : cp target/release/libriichi.so    mortal/libriichi.so
#   #   Windows: cp target/release/riichi.dll      mortal/libriichi.pyd  (需 MSYS2)
#
#   # 權重 .pth 放到專案根目錄的 models/(已 gitignore):
#   curl -L -o models/mortal_298k.pth \
#     https://huggingface.co/VoidShine/mortal-298k/resolve/main/mortal_298k.pth
#
# **不需要 maturin。** Mortal 直接用 cargo 建 cdylib,先前文件寫錯了。
#
# **macOS 的副檔名要改。** 官方建置文件只寫了 Linux 與 Windows。在 macOS 上
# cargo 產出的是 `libriichi.dylib`,但 CPython 的擴充模組載入器只認 `.so`,
# 直接放 .dylib 會 ImportError。改名複製即可,不需要重編。
#
# 實測數據(M5 Pro / 15 核):
#   cargo build --release  32.5 秒(release profile 有 lto=true + codegen-units=1)
#   推論                   14 ms/決策(CPU;torch 的 MPS 後端可用但未實測)
#   權重                   130 MB,mortal 主幹 10.8M 參數,version=4,resnet 192x40
#
# 若要做風格微調(見 README「功能 3」),還需要 Mortal 自己 environment.yml
# 的依賴:tqdm / toml / tensorboard。
